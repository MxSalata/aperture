# API coverage

Every operation of the SysAdmin API v2 specification (273), with the screen of Aperture that calls it, what a real IRIS for Health 2026.2 (Build 221U) instance answered, and whether the online demo answers it. The API Explorer reaches every operation in any case; "Screen" names the hand-made screens that call it directly. Generated by `scripts/coverage-doc.mjs` from the spec index, the source, the demo's mock and [the live sweep](verification/2026-09-28-irishealth-2026.2/coverage-live.json) of 2026-09-27.

## Summary

| | GET | POST | PUT | DELETE | All |
| --- | ---: | ---: | ---: | ---: | ---: |
| Operations in the specification | 115 | 72 | 44 | 42 | 273 |
| Called by a hand-made screen | 64 | 38 | 18 | 19 | 139 |
| Verified on the real instance | 101 | 11 | 16 | 11 | 139 |
| Answered by the online demo | 79 | 42 | 27 | 25 | 173 |

"Verified" means an answer read back from the instance: every GET that could be called with an object that exists (sample objects were created for the ones that had none, see `scripts/live/sample-data.mjs`), and every write in the evidence folders, each undone after its check. Writes that stop, delete or reconfigure what an instance runs on (terminating processes, dismounting or deleting databases, switching journals, licence and mirror changes) were not run here; the demo answers most of them.

## Differences from the specification seen in this run

The sweep checked every answer against the schema the spec declares; the sample data met the rest:

- `GET /v2/database-dirs`: result: spec says object, server sent array (known: spec finding 1).
- `GET /v2/device`: result.Alias: spec says integer, server sent string "" (new).
- `GET /v2/locks`: result[0].Pid: spec says string, server sent integer 874 (known: recorded on 23 September).
- `GET /v2/monitor/dashboard/main`: result.SystemUsage.BusyProcesses[1].Process: spec says integer, server sent string "" (known: spec finding 11).
- `GET /v2/namespace/global-mappings`: result[0].Collation: spec says string, server sent integer 5 (known: recorded on 23 September).
- `GET /v2/security/oauth2/client/server-definitions`: result[0].ID: spec says string, server sent integer 1 (new).
- `GET /v2/security/role/owners`: result[0].AdminOption: spec says boolean, server sent string "0" (known: recorded on 23 September).
- `GET /v2/security/services`: result[0].Enabled: spec says string, server sent boolean true (known: spec finding 9).
- `GET /v2/task`: result.ExpiresDays: spec says integer, server sent string "" (new).
- `GET /v2/web-app`: result.WSGIType: spec says integer, server sent string "WSGI" (new).
- `POST /v2/security/oauth2/client/server-definition?discover=false` answers 500 ("Datatype value 'false' is not a valid boolean"); `discover=0` works.
- `PUT /v2/security/oauth2/client/client-configuration` refuses the body the spec describes: `OAuth2ServerDefinition` is not expected (IRIS takes `ServerDefinition`, spec finding 6), and `RedirectionEndpoint` must be a literal, not the documented object.
- `PUT /v2/security/oauth2/resource-server/mapping` answers 500 on `Service` "CSP" (datatype validation) instead of 400; `PUT /v2/security/oauth2/resource-server` needs an `IssuerEndpoint` that names an existing server definition (422 otherwise).
